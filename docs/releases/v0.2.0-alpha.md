# v0.2.0-alpha

Release title:

```text
AI Workbench MCP: focused Goose recipes and validation policy profiles
```

Python package version: `0.2.0a0`

## Scope

This alpha hardens the v0.1 Goose acceptance workflow with focused recipe and
profile variants for common low-risk engineering work:

- Documentation-only changes.
- Python package maintenance.
- Test-fix work.
- General low-risk coding with deterministic test coverage.

The six-tool acceptance workflow remains stable:

```text
workbench_open_run
workbench_select_model
workbench_record_execution
workbench_validate_run
workbench_quality_gate
workbench_analyze_runs
```

## Recipes

```text
recipes/workbench-docs-only-acceptance.yaml
recipes/workbench-python-package-maintenance.yaml
recipes/workbench-test-fix-acceptance.yaml
recipes/workbench-engineering-acceptance.yaml with validation_profile=low_risk_coding
```

## Validation Profiles

Focused v0.2 policy packs stay as named profiles in
`configs/validation_profiles.yaml`:

```text
docs_only
python_package_maintenance
test_fix
fixture_repair_proof
low_risk_coding
```

Each sign-off profile is command-backed and requires these local evidence
artifacts:

```text
model_selection.json
model_output.md
run_log.jsonl
```

## Example Commands

The focused command examples live in:

```text
examples/focused-workflows/README.md
```

Sanitized focused evidence is committed at:

```text
examples/sample-runs/accepted-docs-only-smoke/
```

## Known Limits

- Goose must be installed and configured separately.
- Focused recipes are starter workflows, not a complete task taxonomy.
- Policy packs are still validation profiles; a first-class policy-pack
  directory is deferred until profile metadata needs a clearer schema boundary.
- Local `runs/` evidence must remain uncommitted.

`low_risk_coding` require evidence artifacts from a six-tool acceptance
workflow before direct validation can pass. Revalidate an existing evidence
