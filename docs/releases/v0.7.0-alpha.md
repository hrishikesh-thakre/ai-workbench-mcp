# v0.7 Version Boundary And Release Candidate Prep

Release-candidate note for source package target `ai-workbench-mcp==0.7.0a0`.

Publication status: not published to TestPyPI, PyPI, or MCP Registry. The latest
published package and registry version remains `ai-workbench-mcp==0.6.0a0`.
Publishing `0.7.0a0` requires a separate approval after fresh release checks.

## Scope

This pass resets the source tree version boundary after the published v0.6
external PR-gate adoption package.

Included source changes:

- `ai-workbench-demo` package-only demo command for synthetic PR-gate outcomes.
- Package-only demo module at `python -m ai_workbench_mcp.tools.demo`.
- MCP core refactor behind the stable `ai_workbench_mcp.core` compatibility
  facade.
- Run analytics refactor behind the existing `run_analyze.py` CLI behavior.
- README and public docs consolidation around package-first onboarding.
- Ruff and pragmatic mypy gates in CI and local development docs.
- Release-hardening tests for root `tools/` shim compatibility and package
  module invocation.
- Fresh local wheel smoke covering console scripts, bootstrap assets, package
  demo, and missing-evidence PR-gate rendering.
- Pre-v1 machine-readable contract fixtures for MCP envelopes, PR-gate
  decisions, analytics projections, and complete run evidence manifests.
- Same-repository GitHub Checks API presentation prototype for the external
  PR-gate workflow, with fork pull requests kept artifact-only.
- Provider cost/time evidence status metadata that separates missing cost
  evidence from provider-backed zero-cost execution.
- Package-module CI and docs command migration while retaining root `tools/`
  compatibility shims.

## Version Boundary

The source package version is `0.7.0a0` in:

- `pyproject.toml`
- `server.json`
- `server.json.packages[0].version`

The external PR-gate workflow defaults remain pinned to the published
`ai-workbench-mcp==0.6.0a0` package until a future release is explicitly
approved. This avoids asking external adopters to install an unpublished source
version.

## Acceptance Rule

This pass does not change acceptance semantics. A PR gate can report `accept`
only from real Workbench run evidence:

```text
validation_report.json
revision_decision.json
```

Missing evidence and scaffold fallback evidence still block with
`pr_gate.acceptance_evidence_missing`.

Fresh wheel smoke proved:

- `ai-workbench-mcp`, `ai-workbench-bootstrap`,
  `ai-workbench-bootstrap-assets`, and `ai-workbench-demo` console scripts are
  installed from the local wheel.

  config assets.
- `python -m ai_workbench_mcp.tools.pr_gate --fallback-run-dir ...` renders a
  deterministic `block` decision for missing evidence.
