# Package Demo Walkthrough

Target length: 90 seconds to 2 minutes.

Use this when you want the fastest public first look at Workbench without Goose, provider credentials, or target-repository setup. The demo uses synthetic fixture evidence generated by `ai-workbench-demo`. It is not a real target-repo acceptance run, provider benchmark, or shortcut around validation and quality-gate evidence.

## Setup

From the repository root:

```bash
python -m pip install -e .
ai-workbench-demo --target ./workbench-first-run
```

If the console script is not on `PATH`, use the packaged module:

```bash
python -m ai_workbench_mcp.tools.demo --target ./workbench-first-run
```

The demo writes three local outcomes:

```text
./workbench-first-run/ai-workbench-demo/accepted/pr_decision.json      -> accept
./workbench-first-run/ai-workbench-demo/needs-review/pr_decision.json  -> needs_review
./workbench-first-run/ai-workbench-demo/blocked/pr_decision.json       -> block
```

Each folder also includes a matching `pr_comment.md` that explains the reviewer-facing next action.

## Recording Script

### 0:00-0:20 - Open With The Problem

AI coding agents can say "done." Workbench asks for evidence: what changed, what validation ran, and whether the quality gate accepted, requested review, or blocked the run.

### 0:20-0:45 - Run The Demo

Run:

```bash
ai-workbench-demo --target ./workbench-first-run
```

Point out that this package-only path does not need Goose, provider credentials, or a target repository.

### 0:45-1:20 - Show The Three Outcomes

Open the generated `pr_decision.json` files:

- `accepted/pr_decision.json` shows `accept`.
- `needs-review/pr_decision.json` shows `needs_review`.
- `blocked/pr_decision.json` shows `block`.

Then open the matching `pr_comment.md` files to show the human-readable reason and required next action for each outcome.

### 1:20-2:00 - Close With The Boundary

This demo is synthetic fixture evidence. A real target-repo acceptance run must provide its own `validation_report.json` and `revision_decision.json` from deterministic validation and the quality gate. Do not commit generated `runs/` evidence or demo output unless it has been intentionally sanitized and moved under an example fixture.
